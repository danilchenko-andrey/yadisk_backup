# Выгрузка photoslice: консольная версия с ограничением доступа

Основана на PXSYS13/yadisk_backup, commit `b8c656bc5667c8fbbbc3cdd84fd85451d468d8ae`.
Доработаны `unlim_download.py` и `unlim_worker.py`. Лицензия MIT сохранена.

**Статус: проверена автономными тестами с вымышленными данными, но ещё не проверена
на живом аккаунте Яндекса.** Сначала соберите список, затем скачайте три файла.
Внутренний API Яндекса не имеет гарантий совместимости. При неожиданном ответе
скрипты останавливаются; они не пытаются угадать недостающие данные.

## Что изменено

- Только стандартная библиотека Python. Для этих двух скриптов не нужен `pip install`,
  `requirements.txt`, OAuth-токен или `.env`. Исходный веб-интерфейс и его установщики удалены.
- Cookies читаются из отдельного файла с правами `600`. Исходные domain, path,
  hostOnly, Secure и expiry учитываются; домены не переписываются. Cookies не сохраняются
  обратно и не печатаются. SameSite/HttpOnly сохраняются как метаданные, но Python
  не является браузером; защиту отправки обеспечивает ограничение адреса назначения.
- Cookies и параметры сессии отправляются **только по HTTPS на `disk.yandex.ru`**.
  Редиректы авторизованных запросов запрещены. Прокси окружения/ОС игнорируются.
- Архивы скачиваются отдельным клиентом **без Cookie, Authorization и Referer**.
  Каждый редирект повторно проверяется. Разрешены только HTTPS:443 и хосты
  `downloader.disk.yandex.ru`, `downloader.yandex.ru`, `*.storage.yandex.net`.
  Иной CDN вызовет остановку, пока его принадлежность Яндексу не проверена и код
  явно не обновлён. Не отключайте проверку TLS и не расширяйте список до любого URL.
- Нет вывода URL с подписью, UID, cookies, sk, HTTP-тел ответов и traceback.
- Список собирается с пагинацией. Пропущенный/повторный кластер, неполный ответ,
  неизвестный размер или изменение ранее перечисленного файла блокируют скачивание.
- База привязана к аккаунту; при смене cookies на другой аккаунт работа останавливается.
- ZIP обязан содержать ровно запрошенный набор файлов. Для каждого проверяются
  размер и CRC, а при наличии исходного MD5 — и MD5. Локальный SHA-256 сохраняется в БД.
  Если MD5 не предоставлен Яндексом, CRC/размер/SHA-256 не доказывают равенство
  удалённому оригиналу: SHA-256 служит для последующей проверки локальной копии.
- Симлинки, специальные файлы, небезопасные пути, лишние элементы и неоднозначные
  имена ZIP отклоняются. Распаковка идёт во временную закрытую папку; публикация
  файлов атомарная. Статус всей порции фиксируется транзакцией только после проверки.
- Одинаковые имена разных фото сохраняются отдельно: `files/<SHA256(resource_id)>/<имя>`.
  Соответствие исходному ID, имени, размеру и локальному пути хранится в SQLite.
- Один процесс на каталог состояния, защищённый системной блокировкой. Нет
  автоматического перехвата «зависшей» порции другим воркером и бесконечных повторов.
- Старая `unlim_state.db` не импортируется: используется новая `manifest-v2.sqlite3`.
  Старым отметкам о скачивании доверять нельзя.

## Требования и границы

Linux VM (основная цель — GCP), Python **3.10+** с актуальными обновлениями ОС,
локальная файловая система с POSIX-правами, блокировками и атомарным rename.
Код рассчитан также на macOS, но испытан только на Linux с Python 3.12.
Windows и папка `rclone mount` для состояния/выгрузки здесь не поддерживаются.

Не запускайте от root. Сессия Яндекса остаётся ценным секретом: root, процессы
с вашим UID и скомпрометированная ОС могут прочитать её. Права `600` — не шифрование.
Используйте отдельную сессию браузера и временную VM, а после переноса отзовите эту
сессию. Секреты не должны попадать в репозиторий, чат, общую папку или Google Drive.

**Photoslice может включать фото как из безлимита, так и из обычных папок.**
Исходный API не даёт здесь проверенного фильтра «только безлимит»; мы не выдаём
число ресурсов photoslice за точное число файлов безлимита. Надпись о полном
списке относится только к полученному снимку API. Сравните периоды/количество с
веб-интерфейсом и не удаляйте оригиналы по одному лишь этому счётчику.

## 1. Подготовка

Из корня этой версии репозитория, под обычным пользователем VM:

```bash
python3 --version
python3 -m unittest discover -s tests -v
umask 077
mkdir -p "$HOME/.local/share/yadisk-unlim-safe"
chmod 700 "$HOME/.local/share/yadisk-unlim-safe"
```

Поместите локальный JSON-экспорт cookies в
`$HOME/.local/share/yadisk-unlim-safe/cookies.json`, затем:

```bash
chmod 600 "$HOME/.local/share/yadisk-unlim-safe/cookies.json"
```

Скрипты **не извлекают cookies из браузера и не устанавливают расширения**.
Используйте только доверенный способ экспорта. Нужен массив объектов с исходными
атрибутами браузера, например структура ниже (значения вымышленные):

```json
[
  {
    "name": "Session_id",
    "value": "EXAMPLE_NOT_A_REAL_COOKIE",
    "domain": ".yandex.ru",
    "hostOnly": false,
    "path": "/",
    "secure": true,
    "httpOnly": true,
    "sameSite": "lax",
    "expirationDate": 2000000000
  }
]
```

Это **пример формата**, не полный список cookies для авторизации. Сессионным cookies
без срока действия не нужно придумывать `expirationDate`. Если файл имеет другие
права, скрипт откажется его читать; автоматического изменения прав чужих файлов нет.
Можно указать другой закрытый путь через `--cookies /absolute/path/cookies.json`.

## 2. Только инвентаризация

```bash
python3 unlim_download.py --collect
python3 unlim_download.py --status
```

Первый шаг не скачивает фотографии. Второй не использует сеть или cookies.
Будут показаны число ресурсов, объём, число файлов без MD5 и завершённость списка.
Для больших кластеров скрипт запрашивает весь диапазон, как upstream, и проверяет
число ресурсов: если сервер ограничивает ответ, сбор остановится, а не объявит
частичный список полным. Повтор `--collect` получает новый снимок; при изменении
набора уже собранных ресурсов потребуется новый `--state-dir`.

## 3. Пробная порция: три файла

```bash
python3 unlim_worker.py --batch 3 --max-batches 1
python3 unlim_worker.py --verify
python3 unlim_download.py --status
```

Локальные оригиналы окажутся в `$HOME/.local/share/yadisk-unlim-safe/files/`.
Откройте полученные три файла. После проверки можно запускать весь список:

```bash
python3 unlim_worker.py
```

Вариант запуска, переживающий закрытие SSH:

```bash
nohup python3 -u unlim_worker.py \
  > "$HOME/.local/share/yadisk-unlim-safe/worker.log" 2>&1 < /dev/null &
```

Не создавайте второй процесс с тем же `--state-dir`. При ошибке скрипт завершится
с ненулевым кодом, оставив порцию pending. После устранения причины запустите ту же
команду. Повторный запуск сначала проверит ранее скачанные файлы по SHA-256.
Проверка `--verify` тоже работает без сети. Она проверяет только скачанную часть;
для полноты всего архива дополнительно проверьте `--status` и отсутствие pending.

## Место и перенос в Google Drive

По умолчанию одна порция: до 25 файлов, до 4 GiB исходных данных, до 5 GiB ZIP.
Перед порцией требуется свободное место под предельный ZIP + текущую распаковку
+ 64 MiB запаса. Файл больше лимита не пропускается: запуск остановится с просьбой
явно увеличить `--max-batch-bytes` (и при необходимости `--max-archive-bytes`).

**Это ограничение временной порции, не всего накопленного архива.** Скачанные файлы
остаются на диске. Автоматическая выгрузка в Google Drive с очисткой буфера пока не
реализована. Не удаляйте локальные файлы между порциями: последующий `--verify`
сочтёт их утраченными. Для начала оцените объём через `--collect` и выделите диск.

Можно выбрать закрытый локальный каталог на отдельном диске:

```bash
mkdir -m 700 /path/to/private-photo-export
python3 unlim_worker.py --output /path/to/private-photo-export --batch 3 --max-batches 1
```

В дальнейших запусках, в том числе `--verify`, используйте тот же `--output`.
Если переносите через rclone, копируйте **только папку `files` (или выбранный output)**,
не родительскую папку с cookies и состоянием. Эта версия сама не загружает в Drive
и не удаляет ни удалённые оригиналы, ни локальные проверенные фото.
При аварийном отключении питания/kill -9 может остаться закрытый `.batch-*` каталог;
не включайте его в перенос. Удалять его можно вручную только при остановленном воркере.

## Проверка изменений

```bash
python3 -m unittest discover -s tests -v
python3 -m py_compile unlim_download.py unlim_worker.py
```

Тесты используют синтетические cookies и ZIP, проверяют ограничения назначения,
редиректы, права, неполные ответы, коллизии имён, повреждение CRC/MD5, распаковку,
повторный запуск, фиксацию состояния и отсутствие секретов в ошибках.
Это проверка конкретных рисков, а не гарантия отсутствия любых уязвимостей.

Остальные скрипты обычного Диска сохранены от upstream и не входят в эту проверку.
`requirements.txt` относится только к ним; не запускайте их установку для photoslice.
